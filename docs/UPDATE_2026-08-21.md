# Agent Olympiad — weekly update (2026-08-21)

**Project:** multi-agent teams on real olympiad contests under contest constraints  
**Collaboration metric:** MultiAgentBench coordination score (Zhu et al., arXiv:2503.01935)  
**Focus contest this week:** ARML Local 2009 (gold-graded, 40 points)

---

## Framing

This benchmark is not “can one unconstrained frontier model solve olympiad problems?”
Frontier models already do well on that setting.

We evaluate **collaboration under contest rules**: shared clock, limited turns and API
budget, allowed tools, submit strategy, and (where relevant) wrong-submit time cost.
We report two axes:

1. **Task score** — correctness vs official gold / sample judges  
2. **Coordination score (CS)** — MultiAgentBench-style collaboration quality

## What shipped this week

### Collaboration score (MultiAgentBench CS)

| Signal | Range | Definition |
|---|---|---|
| Communication (Cscore) | 0–5 | 0 if no team communication; otherwise discussion quality |
| Planning (Pscore) | 1–5 | Quality of planning / coordinated actions |
| **CS** | mean(C, P) | Second reported axis beside task points |

**How scores are assigned.** After each run we do **not** use hand-coded rules
(e.g. message count). An LLM judge reads the logs with MultiAgentBench-style rubrics
(`src/evaluation/collaboration_score.py`):

1. **Communication** — if the chat log is empty → **Cscore = 0** automatically.
   Otherwise the judge sees the task, agent roles/schema, outcome summary, and full
   chat, then returns a 1–5 score plus a short justification (clarity, role fit,
   whether talk helped progress).
2. **Planning** — always judged. The judge sees agent roles and the **action log**
   (speak / scratchpad / sleep / submit / tools) as a proxy for planning, then
   returns 1–5 (clear assignments, roles, workload, whether plans advanced the task).
3. **CS = (Cscore + Pscore) / 2.**

So a solo agent can still have **CS > 0** (e.g. 1.0) even with **Cscore = 0**, because
planning from its own actions can score 1–5. Example: mean(0, 2) = 1.0. A perfect
task score with low CS is expected for solo and is part of the ability-vs-collaboration
story.

### Contest realism

| Gap | Change |
|---|---|
| Flat turn caps | Official `duration_minutes` → turn budget (`contest_budget.py`) |
| Search stubs | Live search + answer-key leak block (`tools_search.py`) |
| ICPC ungraded | Kattis sample `.in/.ans` judge; WA burns 20 minutes of remaining contest clock |
| Thin gold | Curated shorts: ARML Local, ARML National Team, Purple Comet HS/MS, HMMT Guts 2024 |
| Format misses | Gold parser accepts `1.`, `T-1`, semicolon sheets, √/sqrt |

### Baselines

- **single_agent** — equal total resource budget (up to `team_size` calls per turn)
- **centralized / round_table / decentralized** — collaboration protocols
- **Homogeneous teams:** GPT mini, Claude Sonnet, Gemini Flash — every seat uses that model  
- **Heterogeneous team:** multi-agent seats cycle GPT → Claude → Gemini
  (e.g. Group_Leader = GPT, Agent_2 = Claude, Agent_3 = Gemini, …)

**“Hetero × single_agent” is not a mixed team.** `single_agent` has one seat (`Solo`),
so the cycle assigns only the first model (**GPT mini**). That cell is a second GPT
solo run for matrix completeness; real hetero effects are in centralized /
round_table / decentralized.

## Experiment: ARML Local 2009 × models × schemas

Registry budget: **12 turns** (~60 contest minutes). CS enabled.  
Matrix: 4 teams × 4 schemas = 16 cells (**16/16** complete).

Artifact: `results/phase_b/meeting_arml_local/phase_b_matrix.json`

### Task score (/40) and CS (0–5)

Cells show **task · CS**.

| Team | single_agent | centralized | round_table | decentralized |
|---|---:|---:|---:|---:|
| GPT (`gpt-5.4-mini`) | 4.4 · 1.0 | **26.7 · 4.0** | 22.2 · 3.0 | 17.8 · 3.5 |
| Claude (`claude-sonnet-4-6`) | **35.6 · 0.5** | 22.2 · 4.0 | **35.6 · 3.0** | 26.7 · 3.5 |
| Gemini (`gemini-3.5-flash`) | **40 · 1.0** | 35.6 · 3.5 | 35.6 · 3.5 | **40 · 3.0** |
| Hetero (mixed seats) | 13.3 · 0.5 | **35.6 · 3.5** | **40 · 3.0** | **40 · 3.5** |

### Main findings

1. **Ability ≠ collaboration.** Gemini single-agent scores **40/40** with CS **1.0**
   (no teammates → Cscore 0). Multi-agent runs reach CS **≈ 3–4**.
2. **Weaker models gain from teamwork.** GPT mini single-agent is **4.4/40** (one
   early, mostly wrong submit) but centralized reaches **26.7/40** with CS **4.0**.
3. **Heterogeneous multi-agent teams can collaborate well.** The useful hetero
   cells are multi-seat: centralized **35.6/40** (CS 3.5), round_table **40/40**
   (CS 3.0), decentralized **40/40** (CS 3.5). The “hetero single_agent” cell
   (**13.3**) is only one Solo seat → same stack as GPT mini solo, not a mixed team.
4. **High CS does not guarantee max points.** Claude centralized has CS **4.0** but
   task **22.2/40** — coordination quality and answer correctness are separate.

### What “hetero × single_agent” means

`single_agent` always uses one agent (`Solo`). Hetero model assignment cycles
across seats, but with one seat the cycle collapses to the first model
(**GPT mini**). So that cell is **not** “GPT+Claude+Gemini in one body”; it is a
solo GPT run. Compare multi-agent hetero (different models per teammate) for the
actual mixed-team result.

### Why GPT single-agent is low (4.4/40)

Not a broken single-agent baseline:

1. Submitted after **1 of 12** turns (**1** API call), leaving budget unused.  
2. That one-shot sheet was mostly incorrect (e.g. slope `-39` vs gold `-21`).  

Under the same one-shot pattern, Claude scored **35.6** and Gemini **40**. The gap is
model quality plus early stop, not the protocol itself.

## Design choices

1. **Two scores** — task for correctness; CS for collaboration (MultiAgentBench).  
2. **Contest-first matrix** — all models/schemas on one contest before breadth across contests.  
3. **Duration → turns** — reproducible budgets from official contest minutes.  
4. **Equal-budget solo** — fair comparison against multi-agent teams.  
5. **Gold / sample judges first** — deterministic grading where possible.  
6. **Heterogeneous roster routing** — per-seat models for weak-team vs strong-solo stories.
