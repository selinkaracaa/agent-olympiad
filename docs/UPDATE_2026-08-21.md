### 3. MultiAgentBench coordination score (CS)

Implemented in `src/evaluation/collaboration_score.py`, wired into live batches via
`--judge-collab` (on by default for Phase B).

| Signal | Range | Meaning (paper-adapted) |
|---|---|---|
| **Cscore** (communication) | 0–5 | 0 if no team communication; else quality of discussion |
| **Pscore** (planning) | 1–5 | How well the team plans / coordinates actions |
| **CS** | mean(C, P) | Second axis beside task points |

We map our olympiad **chat history** → communication field and **action log** → planning
field, then ask an LLM judge with prompts aligned to MultiAgentBench Appendix A.12.

**Design intent:** task score answers “did they get the math right?”; CS answers
“did they collaborate well under the protocol?” Solo baselines naturally get
**Cscore = 0** (no peers), so CS stays low even if math is strong — that is expected.

## Design choices (why we chose them)

1. **Two scores, not one.** Task grade is verifiable when gold exists; CS is a
   separate collaboration axis from MultiAgentBench so a quiet high-scoring solo
   does not look like “best collaboration.”
2. **Contest-first matrix for demos.** Showing gpt/claude/gemini/hetero on **one**
   contest beats finishing all contests for GPT only — reviewers care about
   model + protocol interaction under identical problems.
3. **Duration → turns, not wall-clock.** Official minutes map to discrete turns so
   runs are reproducible and API-bounded; ICPC 5h → 60 turns is expensive, so the
   meeting slice starts at ARML Local (12 turns).
4. **Equal resource solo.** Solo gets `team_size` calls/turn so “one strong model”
   is not secretly under-budgeted vs a 6-agent team.
5. **Gold / sample judges first.** Prefer deterministic grading (ARML shorts, Kattis
   samples) over LLM judges when the contest deliverable allows it.
6. **Heterogeneous roster.** Weak-team story needs mixed models on one scratchpad;
   `make_roster_caller` routes each agent by system-prompt role.
7. **Daemon + resume.** Long matrices save after every cell and can resume; mid-cell
   progress logs print turn/agent so the run does not look “stuck.”

## How to read these numbers (explanations)

### Why is GPT single_agent so low (4.4/40)?

Not because single-agent is “broken.” Two concrete causes:

1. **Premature submit** — Solo used **1 of 12** turns and **1** API call, then
   called `submit_final`. Equal-budget slots (up to 6 calls/turn) were left unused.
2. **That one-shot answer sheet was mostly wrong** — only ~1/10 gold parts matched
   (e.g. wrong slope `-39` vs gold `-21`). Same protocol, stronger models did fine
   in one shot: Claude **35.6**, Gemini **40**.

So this cell is mainly “**weak model + early stop**,” not “solo can’t score.”

### Why can solo CS be tiny while task is high?

Solo has **no teammates** → MultiAgentBench **Cscore = 0** by design. CS =
mean(0, Pscore) stays low even at 40/40. That is the paper split we want:
**task ability ≠ collaboration quality.**

Examples: Gemini solo **40/40, CS 1.0**; Claude solo **35.6/40, CS 0.5**.

### What does high CS mean here?

Centralized runs that used the full clock (12 turns, ~57 API calls) got **CS ≈ 4.0**
for GPT and Claude: lots of leader↔worker chat + planned delegation. Decentralized /
round_table land around **3–3.5** when there is real discussion.

### Model × protocol patterns (so far)

- **Gemini** dominates task on this packet (35–40/40 across finished schemas).
- **GPT mini** needs collaboration to recover: solo 4.4 → centralized **26.7**
  (and CS 1.0 → 4.0). Team protocols help the weaker model most on this slice.
- **Claude** is strong solo / round_table (35.6); centralized task dipped to 22.2
  despite high CS 4.0 — coordination ≠ automatic max points.
- **Hetero:** solo early-submit is weak (13.3); **centralized mixed roster** already
  **35.6/40** with CS 3.5 — the collaboration story for heterogeneous teams.

### Other grading caveat (from Phase A)

Earlier National Team “zeros” were often **answer-format parse misses**
(`T-1 …`, `a; b; c`), not wrong math. Gold parser v2 fixed that; rescored artifact
`results/phase_a/20260821-155239/phase_a_rescored.json`.
